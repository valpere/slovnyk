## Дії для ручного приймання

1. Перевірити, чи зручно знайти пошук, вибрати напрямок, прочитати групу
   перекладів і перейти на сторінку слова; оцінити вигляд desktop/mobile.
2. Пройти Tab → skip link → Enter → query, заповнити форму й відправити
   без JavaScript. Звірити видимий фокус і порядок елементів.
3. На чистому візиті перевірити мову браузера; змінити UI-мову вручну,
   повторити візит з іншою мовою браузера. Окремо перевірити збереження пари.
4. Перевірити no-match підказку `*` / `?`, зрозумілість помилок і download.
   У preview exact `hello` працює для `en-us → uk-ua`, `привіт` — зворотно;
   `missing` дає no-match, `failure` — 503, `*` — фіксований результат пари.
5. Для кожної прийнятої UI-мови переглянути **всі 29 фраз**, включно з errors,
   у [каталогах](../web/locales/). `legacy-po` також потребує мовного review.
   Перевірити natural wording, native name, однакові терміни та зміст масок.

Посіпака агента `go run ./minions/ui-preview -port 8788` відтворює preview
локально без БД; Ctrl+C завершує процес і прибирає його synthetic scratch.
[Межі й сценарії](../minions/README.md) відрізняють preview від справжнього
SQL пошуку, пагінації, readiness і sitemap. Не перевіряти ними функціональну
повноту сервісу. Агент використовує наявний Chromium CDP 9222, окремий context;
перший візит не перевіряється з cookies попередніх preview.

## Як записати рішення

Для дизайну зафіксувати commit, прийняті views/розміри й конкретні виправлення.
Для мови — код, hash каталогу, усі перевірені фрази та рішення власника.
Додавати нові рішення до DECISIONS; не змінювати `ai-draft` автоматично через
успіх tests або merge PR. Перелік публічних мов і порядок їхнього приймання
залишаються відкритими; цей зріз не обмежує сервіс лише українською/англійською.

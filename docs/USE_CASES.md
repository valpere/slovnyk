# Use cases

Цільовий контракт запропоновано на основі [дослідження](LEGACY.md).
Числові та граничні правила визначені у [requirements](REQUIREMENTS.md).

## Актори

- **Відвідувач:** шукає переклади та завантажує доступні словники без облікового запису.
- **Оператор:** через локальний CLI готує набори, звіряє, публікує та відновлює дані.

## UC-01 — Точний пошук

Відвідувач вибирає мову джерела й призначення, вводить слово або фразу.
Остання обрана пара запам’ятовується між відвідуваннями й підставляється
у форму; явні мови з відкритого посилання мають пріоритет. UI-мова
не змінює збереженої пари. На першому візиті без збереженого вибору система
пропонує мову браузера → англійську; для англомовного браузера —
англійську → українську. Відвідувач може змінити пропозицію. Пропонуються
лише напрямки з даними; якщо відповідного немає, форма пропонує обрати доступний. Якщо вона більше недоступна, форма пояснює це
й пропонує обрати іншу без мовчазної заміни.
Система показує переклади групами: вихідне слово або фраза — заголовок,
під ним — перелік перекладів. Різні оригінальні написання не зливаються
через однаковий нормалізований ключ. Результати подаються сторінками;
якщо група продовжується на наступній, її заголовок повторюється.
Написання з даних зберігається; пошук не залежить від регістру.
Порожній запит повертає форму, відсутність збігів — явне повідомлення
з підказкою використати `*` / `?` для пошуку за маскою. Автоматичних
пропозицій схожих слів або розширення запиту немає.
Невідома мова — помилка вводу; відома пара без даних — «пара недоступна».

## UC-02 — Пошук за маскою

Відвідувач вводить, наприклад, `UKR*` або `S?IE*`; система автоматично
розпізнає маску за `*` чи `?`, без обов’язкового перемикання режиму.
Запит без цих символів за замовчуванням шукається точно.
`*` відповідає нулю або більше Unicode code points, `?` — одному code point
після full case fold та NFC (не grapheme). Широка маска не обходить ліміти й timeout. Наступна сторінка
продовжує той самий набір, порядок і версію даних. Буквальні `*`/`?` можна шукати
в точному режимі. Відвідувач розрізняє неповну сторінку та завершену видачу.

## UC-03 — Мова інтерфейсу

Відвідувач обирає UI-мову незалежно від мов перекладу. Ручний вибір
запам’ятовується між відвідуваннями, зокрема без JavaScript. Пріоритет:
явний підтримуваний `ui`, збережений підтримуваний вибір, підтримувана мова
з `Accept-Language`, далі англійська (`en`) як резервна. Невідомий або більше
не підтримуваний збережений код пропускається.
Автоматичне підлаштування під мову браузера зберігається як важлива функція.
Відсутній переклад UI має явний fallback; код локалі словника не втрачається.
Переклади походять із наявних PO та доповнюються за допомогою ШІ для пропущених
і нових фраз нового UI; формат runtime не прив’язаний до старої реалізації.

## UC-10 — Вхід зі стороннього пошуковика

Відвідувач знаходить сторінку слова/фрази з перекладами через Google або
інший пошуковик. Сторінка доступна без входу й JavaScript; переклади
відповідають адресованому словниковому вмісту. Функція входить у перший
реліз. Сторінка показує переклади лише однією обраною мовою; мовна пара
визначена адресою й не підмінюється збереженими налаштуваннями. Схема URL
уточнюється в [SEO_PLAN](SEO_PLAN.md).

## UC-04 — Завантаження словника

Відвідувач бачить наявні напрямки й завантажує окремий CSV.gz
опублікованої версії для обраної мовної пари. Загальний архів корпусу не потрібен.
Файл містить чотири поля без заголовка: мова джерела, мова призначення,
вихідний текст, переклад. Доступні версія, кількість рядків і checksum.
Відсутній напрямок не отримує порожнього «успішного» експорту.

## UC-05 — Підготовка міграції

Оператор надає явний шлях до незмінного snapshot/експорту. Система інвентаризує
його, визначає формати, рахує записи, перевіряє Unicode, gzip, локалі й дублікати.
Помилкові записи потрапляють у звіт з причиною та позицією, а не зникають.
Dry-run не змінює активного набору. Виявлена неповнота потребує окремого рішення.

## UC-06 — Імпорт і публікація

Оператор імпортує перевірений snapshot у staging, звіряє результат і публікує
цілісну версію. Повтор після збою не подвоює дані. Пошук до завершення публікації
бачить попередній набір. Невдалий імпорт не змінює його. Без проходження перевірок
публікація недоступна; винятки мають бути явно зафіксовані.

## UC-07 — Старе посилання (скасовано)

2026-10-23 користувач відмовився від підтримки старих URL (OQ-04).
Сценарій поза обсягом; ID збережено для історії й не перевикористовується.

## UC-08 — Відновлення та відкат

Оператор відновлює backup на окремій цілі, перевіряє набори й контрольні запити.
У разі проблем перемикає активний dataset або реліз нового сервісу
на попередній перевірений, якщо він є; інакше відновлює працездатність
з перевірених artifacts/backup. Старий сервіс більше не працює, повернення
на нього неможливе. Після повної втрати сервера — відновлення до 24 годин.
Система не видаляє старий snapshot під час перемикання.

## UC-09 — Збереження історичних метаданих

Якщо є dump БД, оператор переносить доступні `count`, `status`, `queries`
з описом походження й невизначеностей. Якщо доступні лише чотирипольні CSV,
звіт прямо вказує, які дані відсутні. З них не виводяться вигадані ваги, статуси
чи статистика. Відсутні дані не блокують читання збережених перекладів.

1: # Architecture
2: 
3: Мова Go та функціональний обсяг підтверджені; наведені технічні рішення —
4: базова пропозиція для реалізації, яку можна змінити з обґрунтуванням.
5: Детальні контракти — у [HLD](HLD.md), критерії — у [requirements](REQUIREMENTS.md).
6: 
7: ## Контекст і межі
8: 
9: ```mermaid
10: flowchart LR
11:     U[Відвідувач] --> W[Go HTTP: HTML та завантаження]
12:     W --> P[(Нова PostgreSQL)]
13:     W --> A[Перевірені експортні артефакти]
14:     O[Оператор] --> C[Go CLI]
15:     S[Незмінний legacy snapshot] --> C
16:     C --> P
17:     C --> A
18: ```
19: 
20: Старий runtime і його БД не є залежностями обслуговування нового сайту.
21: Перемикання домену/проксі — окрема операція після репетиції міграції.
22: Імпорт приймає контрольовані локальні файли; HTTP не приймає довільні URL чи uploads.

24: ## Рішення
25: 
26: | ID | Рішення | Причина й компроміс |
27: |---|---|---|
28: | ADR-01 | Модульний Go-моноліт: HTTP і CLI зі спільними application/domain пакетами. | Одна модель правил, проста експлуатація; міграція запускається окремим процесом і не займає HTTP workers. |
29: | ADR-02 | PostgreSQL як цільова БД з новою схемою й версійними міграціями. | Транзакційна публікація, індекси й потокове завантаження великого корпусу; потребує окремої БД. Не переносити таблицю на кожну мову. Остаточну місткість підтвердити вимірюванням. |
30: | ADR-03 | Серверний HTML через `html/template`, CSS, мінімальний необов'язковий JS. | Пошук доступний без JS; окремий SPA не потрібен для підтверджених сценаріїв. |
31: | ADR-04 | Незмінні dataset versions, staging і атомарний active pointer. | Не показує частковий імпорт, спрощує rollback; потребує місця для кількох наборів і політики retention після запуску. |
32: | ADR-05 | Raw texts зберігаються, нормалізований ключ — похідний і версійний. | Пошук без регістру не руйнує апострофи, варіанти письма та оригінальні значення. |
33: | ADR-06 | Експорти готуються до публікації й адресуються через маніфест. | Вебзапит не генерує великий файл; артефакт публікується тільки після завершення та перевірки hash. |
34: | ADR-07 | Спочатку точний пошук і контрольовані маски; без Elasticsearch/vector/LLM. | Саме це потрібно для підтверджених use cases. Додаткові індекси — після вимірювань, без зміни контракту результату. |
35: | ADR-08 | Операторські зміни через CLI з окремими правами; вебсервіс читає словник. | Відсутня потреба в admin UI й користувацьких облікових записах першої версії. |

37: ## Межі модулів
38: 
39: - **Catalog** знає локалі, доступні напрямки та версію набору.
40: - **Lookup** визначає нормалізацію, режими, порядок, cursor і обмеження.
41: - **Presentation** відображає дані, локалізує UI й адаптує підтримувані старі URL.
42: - **Import** парсить legacy-формати й зберігає provenance; не змінює семантику Lookup.
43: - **Publication** перевіряє набір, перемикає active pointer, керує експортами й відкатом.
44: - **Operations** забезпечує конфігурацію, diagnostics і перевірку restore.
45: 
46: Домен не залежить від HTTP, legacy-таблиць чи файлових шляхів. Не вводити
47: універсальну систему плагінів або складний repository framework без потреби.
48: 
49: ## Межі довіри й експлуатація
50: 
51: Публічний ввід проходить перевірку до запиту в БД; SQL параметризований,
52: HTML екранований. Назва таблиці не утворюється з коду локалі. HTTP має окремий
53: обліковий запис БД з читанням опублікованих наборів; CLI має запис лише в новій БД.
54: Облікові дані не записуються в Git, маніфести чи логи. TLS завершується на
55: налаштованому reverse proxy або в сервісі відповідно до майбутнього deployment.
56: 
57: Пошук має timeout і ліміт сторінки; широкий wildcard може бути відхилений
58: як надто дорогий. Зовнішні кеші, репліки й partitioning не є початковою вимогою.
59: Точні версії Go/PostgreSQL, ресурсні бюджети, RPO/RTO та deployment задаються
60: перед відповідним інтеграційним етапом, а не видаються за виміряні зараз.

FILE docs/DATA_MODEL.md
1: # Модель даних V1
2: 
3: Статус: конкретизація запропонованих технічних рішень HLD, ще не SQL-міграція.
4: Цей документ визначає ключі й інваріанти; реалізація має забезпечити їх DDL,
5: транзакціями та verify. Поведінкові вимоги залишаються у REQUIREMENTS.
6: 
7: ## Типи та ідентичність
8: 
9: Dataset ID — UUID. Translation ID — додатний bigint, унікальний у dataset.
10: Artifact/tuple/key/fingerprint digest — 32 байти SHA-256, не текст довільної довжини.
11: Locale code — непорожній UTF-8 рядок до 64 bytes, без NUL; дозволений лише код
12: з маніфесту. Не вимагати відповідності сучасному BCP-47 від legacy-кодів.
13: Source/target text — непорожній UTF-8 без NUL, до 64 KiB **кожне поле** у V1.
14: Це захисний admission limit, не висновок про довжини реального корпусу.
15: Більші значення потрапляють у quarantine та потребують зміни версійного контракту
16: або погодженого винятку; ніколи не обрізаються для успішного імпорту.
17: 
18: Mapping V1 — **identity**: чотири декодовані поля зберігаються буквально,
19: включно з кодами локалей і крайніми пробілами. Aliases працюють лише у HTTP.
20: `sr-sp` не зливається з `sr-rs`. Майбутній неідентичний mapping потребує окремого
21: рішення щодо raw identity та експорту; його не можна увімкнути непомітно.
22: 
23: Tuple digest рахується з чотирьох полів у порядку `source_locale`,
24: `target_locale`, `source_text`, `target_text`: для кожного — uint64 big-endian
25: довжина UTF-8 bytes та самі bytes. Duplicate — рівність усіх чотирьох полів,
26: а не лише hash. Різні tuples з одним hash зупиняють імпорт/verify як collision.
27: Нормалізований ключ — NFC → full Unicode case folding → NFC; жодного trim.
28: Його hash — SHA-256 UTF-8 ключа. Exact завжди перевіряє ще й рівність ключа.
29: 
30: ## Таблиці та обов'язкові обмеження
31: 
32: | Таблиця | Ключ, поля та інваріант |
33: |---|---|
34: | `datasets` | PK `id`; UNIQUE fingerprint; manifest bytes/hash, schema/parser/mapping/normalization versions, state, timestamps. Готовий набір незмінний. |
35: | `active_dataset` | Singleton PK з CHECK id=1; nullable dataset ID, bigint generation >=0. FK лише на готовий набір через publication service. |
36: | `dataset_locales` | PK `(dataset_id, code)`; raw code, nullable display name. |
37: | `dataset_pairs` | PK `(dataset_id, source_locale, target_locale)`; composite FK обох локалей; unique_count bigint >=0. |
38: | `translations` | PK `(dataset_id,id)`; composite FK на pair; чотири raw поля, source_key, key_hash, tuple_hash; UNIQUE `(dataset_id,tuple_hash)` з обов'язковою collision check до merge. |
39: | `source_files` | PK `(dataset_id,artifact_hash)`; original relative name, format, byte size, completion/checksum state; один hash не можна двічі включити у manifest. |
40: | `import_records` | PK `(dataset_id,artifact_hash,ordinal)`; ordinal від 1; outcome unique/duplicate/rejected, nullable translation ID, nullable issue code; composite FK до file/translation того самого dataset. |
41: | `translation_origins` | PK і FK на accepted import_record; translation ID, чотири raw поля, nullable legacy count/status, source locator і provenance. Є для unique **та** duplicate occurrences. |
42: | `import_runs` | UUID run ID, dataset FK, attempt, checkpoint per artifact, state/error class; лише один writer dataset. |
43: | `import_issues` | Dataset/artifact/ordinal або byte offset, reason code, контрольований quarantine reference; жодних секретів. |
44: | `legacy_query_snapshots` | Dataset, artifact/ordinal, raw input/output locale, word, nullable count int64, nullable raw modified timestamp, timezone known/unknown; не live-лічильник. |
45: | `publication_events` | Generation PK; previous/new dataset IDs, operator/run reference, timestamp; append-only. Підтверджує право cursor читати retained version. |
46: | `exports` | PK `(dataset_id,export_id)`; FK pair, relative artifact reference, SHA-256, bytes, logical rows, verified flag. |
47: 
48: Nullable `count/status` — int64 зі збереженням 0 і від'ємних значень, якщо вони
49: є в snapshot; невідомі значення — NULL, не default 1. Source timestamps зберігаються
50: як raw text і опис типу, без вигаданого UTC. Точний DB adapter затверджується після
51: аудиту живої схеми OQ-02. Записи з несумісними типами блокують verify або мають
52: окреме погоджене рішення; conversion не допускає silent overflow.
53: 
54: ## Індекси й незмінність
55: 
56: Початковий exact index: `(dataset_id,source_locale,target_locale,key_hash)`;
57: residual `source_key = query_key` обов'язковий. Не індексувати необмежений text
58: кортеж B-tree. Mask спочатку використовує pair filtering, параметризований LIKE,
59: sort і timeout; оптимізація після EXPLAIN на корпусі. Порядок — C collation за
60: `(source_key,source_text,target_text,id)`, не locale-dependent collation.
61: 
62: Після ready заборонені зміни translations, origins, каталогу й manifest;
63: окремий export verification/publish event не змінює вміст набору. FK та verify
64: забороняють cross-dataset references. HTTP DB role не пише у ці таблиці;
65: вибір опублікованого dataset виконується application service, не довільним ID клієнта.

40: ## FUN-CATALOG — довідник і версії
41: 
42: Модель зберігання (DDL створюється при реалізації); точні ключі, типи та
43: інваріанти — у [DATA_MODEL](DATA_MODEL.md):
44: 
45: | Сутність | Ключові поля та правила |
46: |---|---|
47: | `datasets` | ID, manifest hash, parser/mapping/normalization versions, state, timestamps; незмінна після ready |
48: | `active_dataset` | Один рядок з dataset ID і generation; publish/rollback — lock + expected-generation CAS |
49: | `dataset_locales` | `(dataset_id, code)`, назва; сирі legacy-коди зберігаються, aliases окремо |
50: | `dataset_pairs` | `(dataset_id, source_locale, target_locale)`, число унікальних зв'язків, export reference |
51: | `translations` | ID, dataset ID, source/target locale, source/target text, source search key |
52: | `source_files` | Dataset, artifact hash, relative name, format, bytes, logical record counts, validation state |
53: | `translation_origins` | Translation ID, source file/record locator, чотири сирі поля до mapping, nullable legacy count/status; усі входження дублікатів |
54: | `import_runs` | Dataset, run identity, state, batch checkpoints, totals, failure reason |
55: | `import_issues` | File, locator, issue code, безпечний опис; raw record в окремому контрольованому quarantine за потреби |
56: | `legacy_query_snapshots` | Доступні поля `queries`, raw timestamp без timezone, походження; не нова live-аналітика |
57: | `exports` | Dataset/pair, artifact path, content hash, compressed bytes, logical record count |
58: 
59: Логічна унікальність перекладу: dataset + чотири **оригінальні** значення.
60: Не покладатися на B-tree всього довгого текстового кортежу: при реалізації
61: використати bounded digest key з перевіркою рівності оригіналів; hash collision
62: має зупинити verify з явною помилкою, а не злити різні записи.
63: Нормалізований ключ не унікальний. Ідентичні ключі не об'єднують написання.
64: Усі посилання обмежені одним dataset; FK та verify перевіряють цілісність.

68: ## FUN-LOOKUP — пошук
69: 
70: HTTP-контракт пропозиції: `GET /search?from=uk-ua&to=en-us&q=...&mode=exact&ui=uk&cursor=...`.
71: `mode` — `exact` або `mask`. `GET /` показує форму; `GET /languages` — каталог.
72: HTML — основний інтерфейс; публічний JSON API поки не обіцяється.
73: 
74: 1. Перевірити розмір, UTF-8, локалі, mode і cursor. Початкові конфігуровані
75:    defaults: 1024 Unicode code points запиту, 8 KiB query text, 50 зв'язків
76:    на сторінку, максимум 100; DB timeout 2 s. Це захисні defaults, не SLO.
77: 2. Зафіксувати dataset ID на перший запит. Обрізати крайні пробіли запиту,
78:    застосувати NFC → Unicode case folding → NFC; так само будувати ключ з
79:    source text, але без обрізання/очищення raw values. Версію бібліотеки та
80:    Unicode-даних фіксувати у normalization version.
81: 3. Exact використовує рівність ключа. У mask `*` компілюється в `%`, `?` у `_`,
82:    буквальні `%`, `_` та escape-символ екрануються для SQL LIKE з явним ESCAPE.
83:    Довільні regular expressions і SQL від клієнта не приймаються.
84: 4. Сортування за `(source_key, source_text, target_text, id)` з визначеною
85:    bytewise/C collation. Page обмежена rows і serialized bytes; lookahead встановлює `has_more`. Групування source text
86:    виконується лише в межах сторінки; велика група може продовжуватися на наступній.
87: 5. Cursor містить dataset, fingerprint параметрів і anchor translation ID,
88:    з якого сервер відновлює sort tuple; повних текстів у token немає;
89:    перевіряється цілісність і межі. Неправильний cursor → 400, недоступна стара
90:    версія → 410 з пропозицією повторити пошук. Dataset не змінюється між сторінками.
91: 
92: Детальний контракт HTTP, code points після fold, dataset pin до валідації
93: та byte budget — у [LOOKUP_CONTRACT](LOOKUP_CONTRACT.md).
94: Індекс exact: dataset + pair + digest нормалізованого ключа + residual equality.
95: Не створювати B-tree з повними довгими текстами. Для mask — виміряти prefix
96: та infix плани; не обіцяти швидкий `%...%` без вимірювань. Усі режими під timeout.
97: Timeout → явна помилка обмеження (503), а не «нічого не знайдено».
98: Новий збір `queries` у цей потік не входить.

102: ## FUN-UI — інтерфейс і сумісність
103: 
104: Каталоги локалей словника відокремлені від UI-кодів. Явний підтримуваний `ui`
105: має пріоритет над `Accept-Language`; потім configured default. Якщо alias
106: мовного коду неоднозначний, не вибирати варіант мовчки. Пропозиція стартового
107: UI — українська й англійська; повний перелік після OQ-06.
108: 
109: Legacy adapter знає лише явний allowlist handlers і параметрів. `sel`/`pre`
110: автоматично обирають mask, якщо `iw` містить `*`/`?`, як старий пошук; нова форма
111: має явний mode. Для `pre` — UTF-8 `text/plain` з тим самим обмеженим результатом
112: і позначенням продовження. `hom`/`dwn`/`loc` можна зіставити новим сторінкам;
113: `top` показує повідомлення про недоступність статистики, доки її не реалізовано.
114: Підтверджений path `/fcgi-bin/dic.fcgi`, mapping і deliberate changes — у
115: [LEGACY_COMPATIBILITY](LEGACY_COMPATIBILITY.md). Невідомі server aliases — OQ-04.

117: <a id="fun-import"></a>
118: 
119: ## FUN-IMPORT — інвентаризація та завантаження
120: 
121: Два окремі adapters: legacy CSV4.gz і описаний DB snapshot export. П'ятипольний
122: CSV отримує власний format ID лише після аудиту: його не вгадувати по одному рядку.
123: CSV читається lossless parser за [IMPORT_CONTRACT](IMPORT_CONTRACT.md),
124: не `encoding/csv.Reader`, який змінює embedded CRLF. Gzip перевіряється до EOF; рядок текстового файла
125: не дорівнює CSV-запису з quoted newline. Правила порожніх полів, BOM і додаткових
126: колонок явні: порожні мови/тексти, хибний UTF-8 та неочікувані колонки → issue;
127: BOM допускається лише на початку файла й враховується у parser version.
128: 
129: Source manifest перелічує очікувані файли з SHA-256, parser/mapping versions,
130: обраним джерелом істини, очікуваними локалями, відомими пропусками й exceptions.
131: Шлях не визначає ідентичність запису сам по собі. Fingerprint імпорту складається
132: з канонічного маніфесту вмісту й versions; зміна байтів або правил — новий dataset.
133: Mapping V1 — identity; aliases існують лише в HTTP adapter. Непомітного
134: злиття raw locale codes немає.
135: 
136: Import state: `created → loading → validating → ready`; помилка → `failed`.
137: Активність — окремий pointer, не додатковий mutable стан рядків перекладів.
138: Batch і checkpoint комітяться разом, імпорт одного fingerprint захищений lock.
139: Для gzip без надійного seek повтор може читати від початку; committed records
140: ідентифікуються за source artifact + logical record index і не дублюються.
141: Файли поза маніфестом не потрапляють у імпорт мовчки.
142: 
143: <a id="fun-publish"></a>
144: 
145: ## FUN-PUBLISH — звіряння, експорт і публікація
146: 
147: Verify перевіряє облік записів/файлів, сирі значення, provenance, локалі, дублікати,
148: детерміновані per-pair digests від відсортованих length-prefixed UTF-8 кортежів,
149: а також контрольні exact/mask queries. Самі counts не доводять рівність даних.
150: Якщо CSV recovery ненадійний або не завершено gzip, файл failed; його totals
151: не видаються за повний облік записів. Рішення щодо кожної втрати зафіксоване.
152: 
153: До ready формуються та перевіряються експорти через temp file → завершення →
154: hash → atomic rename на одному filesystem. Публікація перевіряє наявність
155: артефактів і validation report, бере DB lock, перевіряє expected generation та змінює active pointer і generation
156: одним commit; stale команда отримує conflict. Деталі retry/verify/CAS —
157: [IMPORT_CONTRACT](IMPORT_CONTRACT.md).
158: Артефакт без commit може бути orphan і прибирається лише окремим maintenance;
159: активний набір ніколи не посилається на незавершений файл.
160: Старі версії зберігаються для cursor і rollback за майбутньою retention policy.
161:

164: ## FUN-EXPORT — завантаження
165: 
166: `GET /downloads` показує manifest активного набору; файл видається за непрозорим
167: ID, не за довільним path. `Content-Disposition: attachment`, тип gzip; SHA-256
168: та logical record count доступні поруч. Export CSV4 є сумісним обміном перекладів,
169: а не повним backup метаданих. Відсутня пара → 404. Публічний доступ до artifacts
170: включається після OQ-05; до цього тести — на синтетичних fixtures.

175: 
176: `GET /healthz` — живий процес; `/readyz` — підключення до БД, сумісна schema

6: ## Маніфест та fingerprint
7: 
8: Оператор готує immutable snapshot і manifest JSON schema version 1: source kind,
9: authority/snapshot date або unknown, rights status, список artifacts, locales,
10: expected pairs, parser/mapping/normalization versions, admission limits,
11: відомі пропуски, exceptions. Кожен artifact має SHA-256 вихідних bytes, size,
12: relative name, format ID, очікувану пару або явне multi-pair позначення.
13: Невідомі поля, дубльовані JSON keys, невідомий format/version — помилка.
14: Paths лише відносні, без `..`, symlinks чи виходу зі snapshot root.
15: Однаковий artifact hash двічі в manifest — помилка, навіть під різними іменами.
16: 
17: Fingerprint = SHA-256 canonical manifest bytes: UTF-8 JSON без whitespace,
18: keys лексикографічно, без float values; artifacts відсортовані за hash,
19: локалі/пари/винятки — за канонічним JSON представленням. Значущі **всі** поля,
20: включно з іменами та exceptions. Канонічний encoder version входить у schema version;
21: реалізація постачає golden bytes/hash fixture. Host-specific absolute paths
22: і run timestamps у fingerprint не входять і зберігаються окремо.
23: Зміна bytes, правил, лімітів чи exceptions — новий fingerprint/dataset.
24: 
25: ## CSV4.gz: lossless-csv4-v1
26: 
27: Чотири поля без заголовка: source locale, target locale, source text, target text.
28: UTF-8, comma delimiter; quoted field починається `"`, literal quote — `""`.
29: LF або CRLF поза лапками завершують record; усередині лапок LF/CRLF/CR
30: зберігаються буквально. Bare CR поза лапками — fatal syntax error.
31: Після closing quote допустимі лише delimiter, record end або EOF.
32: Final record без newline допустимий. Порожній фізичний рядок — один record
33: з неправильним field count, не silently skipped. UTF-8 BOM дозволений лише
34: на початку decompressed file і знімається як file marker; у полях це звичайний символ.
35: 
36: **Не використовувати `encoding/csv.Reader` як lossless parser:** він нормалізує
37: CRLF усередині поля. Потрібен parser з цим контрактом і відповідними fixtures.
38: Вихідні compressed artifacts зберігаються окремо, щоб відтворити оригінальні bytes.
39: Export writer також мусить пройти CR/LF round-trip: декодовані поля незмінні.
40: 
41: Поле понад 64 KiB, порожня мова/текст, NUL, invalid UTF-8, не 4 поля,
42: код/пара поза manifest — rejected з reason і locator. Ліміт parser record —
43: 1 MiB decompressed bytes, artifact — 16 GiB decompressed bytes у V1; ці limits
44: версійні, не доказ відповідності corpus. Якщо parser не може безпечно знайти
45: кінець oversized/malformed record, файл failed, повний parsed count unknown.
46: Gzip читається до EOF з перевіркою checksum/trailer; concatenated members
47: декодуються як один потік, trailing non-gzip bytes — failure. Усі input bytes
48: звіряються з manifest до завершення verify. Fatal file failure блокує ready.
49: 
50: ## DB snapshot adapter
51: 
52: CSV4 не відновлює metadata. Окремий `legacy-db-jsonl-v1` вимагає header з source
53: schema hash, snapshot ID, encoding і явним table-to-locale mapping. Наступні
54: JSONL records мають kind translation/query/locale, source table + row locator,
55: типізовані nullable поля і raw metadata. Int64 передаються decimal strings;
56: unknown відокремлений від 0; timestamps — raw string + source type + timezone
57: status. JSON parser відхиляє duplicate keys. Raw export зберігається незалежно
58: від SQL admission. Формат не вважається готовим adapter до затвердження точної
59: JSON Schema та перевірки реальної БД (OQ-02); не вгадувати її з saved DDL.
60: 
61: ## Retry та облік
62: 
63: `created → loading → validating → ready`; terminal validation/syntax failure →
64: `failed`. Ready незмінний. Один writer на fingerprint під DB lock; run має
65: attempt ID. Втрата процесу/DB connection — retryable interruption: lock звільняється,
66: новий attempt продовжує loading/validating лише з незмінним manifest. Fatal failed
67: не resume-иться: потрібна нова версія manifest/правил; повтор діагностики допустимий
68: без запису і без переходу failed → ready.
69: 
70: Record ordinal — логічний номер від 1 в artifact. Batch records, origins,
71: issues і checkpoint комітяться однією транзакцією. Replay gzip від початку
72: перевіряє prefix bytes/identity та пропускає вже committed ordinals; не додає origins
73: повторно. `accepted_unique` належить першому входженню за artifact hash/ordinal;
74: порядок обробки детермінований. Metadata конфліктних origins не усереднюються.
75: 
76: Для повністю розібраного artifact:
77: `parsed = accepted_unique + duplicate_occurrences + rejected`.
78: Для failed artifact totals — лише підтверджений prefix, completion=false.
79: Exceptions мають перелічувати конкретні hashes/locators/reasons і рішення;
80: загальне «ігнорувати помилки» недопустиме. Виключення цілого artifact потребує
81: нового manifest зі збереженим описом excluded source та звітом втрати.
82: 
83: ## Verify та active pointer
84: 
85: Verify звіряє всі artifacts, tuple bytes, counts, origins, FK, per-pair sorted
86: length-prefixed tuple digests, metadata та контрольні запити. Експорти і report
87: готуються до ready: temp → complete → SHA-256 → atomic rename на одному filesystem.
88: Verify report прив'язаний до dataset fingerprint і hashes усіх exports.
89: Неперевірений/незавершений файл не може бути посиланням ready dataset.
90: 
91: Операторські команди publish/rollback обов'язково мають `--expected-generation N`.
92: Транзакція блокує singleton active row, порівнює generation, перевіряє ready/report/
93: artifact availability, перемикає ID та збільшує generation на 1. Stale N → conflict,
94: без зміни pointer; це захищає і від ABA-перемикань. Rollback — така сама CAS-операція
95: до retained ready version, не редагування даних. Перший publish очікує generation=0.
96: Cursor readers бачать immutable old або new dataset. GC/retention не виконується
97: автоматично у V1; будь-яке видалення потребує окремої процедури та backup.
98: 
99: ## Обов'язкові fixtures до реалізації
100: 
101: Quoted CRLF/LF/CR, final record без LF, blank record, BOM, doubled quotes,
102: invalid UTF-8/NUL, oversized field, wrong columns, truncated gzip/trailer,
103: duplicate artifact hashes, repeated tuple з різним metadata, hash collision injection,
104: retry після кожного batch, retry validating, stale publish/rollback та ABA.
105: Для DB adapter: NULL/0/negative metadata, timestamp без timezone, schema mismatch.
106: Це додаткові критерії AT-06–11/18, не твердження про пройдені тести.

39: ## Mapping параметрів
40: 
41: Один strict URL decode (`+` → space, `%2B` → plus), bounded UTF-8 parsing;
42: duplicate відомого key → 400, malformed escapes/NUL → 400. Загальні limits LOOKUP
43: діють до adapter. Unknown keys (включно з hl) ігноруються, не стають aliases hn.
44: `iw` зберігає punctuation і whitespace до нормалізації LOOKUP; старе руйнівне
45: очищення **не відтворюється**. Є `*`/`?` → mode mask, інакше exact. `%252A`
46: після одного decode — буквальне `%2A`, не wildcard.
47: 
48: Мовні коди il/ol/ul: ASCII lowercase, underscore → hyphen **лише тут**.
49: Повні dictionary codes шукаються буквально у pinned dataset. Fixed short aliases:
50: `uk → uk-ua`, `en → en-us`; інші короткі коди → 400 до явного розширення таблиці.
51: Якщо exact повний код існує, він має пріоритет; en-gb ніколи не зливається з en-us.
52: UI map для стартової пропозиції: uk-ua/uk → uk, en-us/en-gb/en → en; інше → UI fallback.
53: 
54: Для sel/pre missing il → resolved UI dictionary default (uk→uk-ua, en→en-us);
55: missing ol → en-us; явно порожня/невідома il/ol → 400. Missing/empty iw → форма 200
56: (для pre — коротка plain-text інструкція). Same-locale дозволено за наявності пари:
57: це виправлення старого обмеження, потрібне для імпортованого sr-rs→sr-rs.
58: 
59: Continuation URL веде на новий `/search` із явними from/to/q/mode/limit/cursor/ui;
60: для pre також `format=plain`. На новому endpoint format відсутній/html → HTML,
61: plain → UTF-8 text/plain, інший/empty/duplicate → 400. Format не входить у cursor
62: fingerprint: ті самі entries/порядок, але byte budget визначається actual encoding.

FILE docs/LOOKUP_CONTRACT.md
1: # Контракт пошуку V1
2: 
3: Конкретизація FUN-LOOKUP/UI; API нижче — цільовий, ще не реалізований.
4: Основний результат — server-rendered HTML без JavaScript.
5: 
6: ## HTTP та помилки
7: 
8: `GET /search?from=uk-ua&to=en-us&q=слово&mode=exact&limit=50&ui=uk`
9: 
10: | Вхід / подія | Результат |
11: |---|---|
12: | Немає `q` або q після trim порожній | 200 форма без SQL lookup; cursor з порожнім q → 400 |
13: | Немає from/to при непорожньому q | 400 з формою вибору; new endpoint не вгадує пару |
14: | Немає mode / limit | exact / 50; explicit empty або невідоме значення → 400 |
15: | limit поза 1..100, не decimal integer | 400 |
16: | Duplicate відомого параметра, malformed percent/UTF-8, U+0000 | 400; parsing тільки один раз |
17: | Невідома locale | 400; відома, але відсутня пара → 404 з поясненням |
18: | Немає active dataset / DB unavailable / DB timeout | 503; це не порожній результат |
19: | Немає збігів | 200 з явним empty result |
20: | Cursor invalid/signature mismatch/parameters changed | 400 |
21: | Cursor dataset або його normalizer недоступний | 410; запропонувати почати заново |
22: | Raw request-target понад 32 KiB | 414 до parsing |
23: | Decoded q понад 8 KiB або 1024 code points | 400 до lookup |
24: 
25: Empty from/to і cursor — invalid, якщо передані. Unknown query keys ігноруються
26: після перевірки encoding і загального розміру. ASCII controls U+0001..001F/007F
27: у q заборонені, **крім TAB/LF/CR**, які можуть бути частиною raw field.
28: Відомі текстові параметри перевіряються як UTF-8; жодного другого URL decode.
29: UI: explicit supported ui → Accept-Language supported match → configured default;
30: unsupported/empty ui переходить до fallback, відображається фактично обрана мова.
31: `format` відсутній/html → HTML, plain → text/plain, інший/empty → 400;
32: format не входить у cursor fingerprint. UI не змінює словникову пару. locale aliases для нового endpoint не застосовуються.
33: 
34: ## Нормалізація та маски
35: 
36: Обрізати крайні Unicode White_Space **тільки запиту**, потім NFC → full case fold
37: → NFC. Normalization version фіксує реалізацію, Unicode tables і trim set.
38: Source key не обрізається. Тому raw ` слово ` exact-формою не знаходиться;
39: mask `*слово*` знаходить його. Оригінал доступний в експорті. Це свідомий контракт
40: сумісний з FR-02, а не прихована чистка даних.
41: 
42: Exact сприймає `*`/`?` буквально. У mask `*` — нуль або більше Unicode code points,
43: `?` — один code point **після** нормалізації, не grapheme. Немає escape-синтаксису
44: для literal wildcard у mask; для нього використовувати exact. LIKE compiler
45: заміняє wildcard tokens і екранує literal `%`, `_`, `\` з явним SQL ESCAPE.
46: Key/pattern і cursor bounds передаються лише як SQL parameters.
47: 
48: Приклади: `ß → ss`, тому `?` не збігається з цим ключем, `??` збігається;
49: `e + combining acute → é`, для нього достатньо `?`; ZWJ emoji може потребувати
50: кількох `?`. Діакритика, внутрішні пробіли, апострофи та punctuation значущі.
51: 
52: ## Dataset pin, порядок і cursor
53: 
54: Без cursor читати active ID один раз; далі всі catalog/key/search queries
55: працюють тільки з ним. З cursor: спочатку перевірити bounded token і HMAC,
56: вибрати **dataset з cursor**, завантажити його normalizer і лише після цього
57: перевіряти locales/pair та нормалізувати q. Новий active не впливає на продовження.
58: Dataset з token має бути раніше опублікований і retained; довільний staging ID
59: не дає доступу до даних. Publication history зберігає факт publish.
60: 
61: Порядок C/bytewise: `(source_key, source_text, target_text, id)`; seek predicate
62: використовує ту саму collation і strict greater-than. Source grouping лише
63: всередині сторінки; велика група продовжується на наступній сторінці.
64: 
65: Cursor — base64url canonical JSON payload + HMAC-SHA256, максимум 2048 bytes:
66: `version, kid, dataset_id, fingerprint, anchor_translation_id, limit`.
67: Fingerprint — SHA-256 length-prefixed UTF-8 values `normalization_version, from,
68: to, mode, normalized_q, decimal_limit`. UI не входить. Token не містить raw texts
69: чи повного sort tuple. Сервер отримує boundary tuple з immutable translation
70: за dataset+anchor ID та перевіряє, що anchor належить парі й відповідає фільтру.
71: HMAC constant-time check; unknown kid → 400. Old signing keys зберігаються на
72: весь строк підтримки cursors; заміна ключа без retention робить старі tokens invalid.
73: Формат token і serialization мають golden fixtures до реалізації.
74: 
75: Page обмежена limit **і 1 MiB serialized response body**. Формувати bounded buffer
76: до headers, включати лише цілі entries; reserve для templates/continuation/error
77: UI — 128 KiB, а один entry з двома полями до 64 KiB має вміститися з HTML escaping.
78: Renderer зобов'язаний перевіряти цю верхню межу; oversized шаблон/entry — явна 503,
79: не обрізання тексту. Коли byte limit зупинив видачу, cursor вказує на останній
80: включений entry, а не на прочитаний наперед. Наявність наступного entry визначає
81: has_more. Page може бути коротшою за limit. Загальний DB deadline — 2 s від початку
82: lookup, не 2 s на кожен SQL; cancellation доходить до драйвера.
83: 
84: ## Індекси й перевірки
85: 
86: Exact: bounded key_hash index + residual equality source_key; normalized collisions
87: не зливають raw variants. Mask може сканувати pair під deadline; швидкість infix
88: не обіцяється без вимірювання. План та memory/sort budget перевірити у rehearsal.
89: 
90: AT-02/03/04/05/15/16 доповнюються fixtures: fold expansions, composed/decomposed,
91: ZWJ, literal SQL metacharacters, edge spaces, long fields, byte-limited pages,
92: forged/oversized cursor, changed params/limit, key rotation, new active зі зміненим
93: каталогом/normalizer, retained old dataset, відсутній old dataset → 410.

46: ## Загальні правила приймання
47: 
48: Оригінал — декодовані значення полів без очищення; вихідні архіви зберігаються
49: окремо для відтворення байтів. Дублікат — однакові чотири оригінальні поля
50: в межах набору; його походження та кількість входжень не втрачаються.
51: Колізія нормалізованих ключів не є дублікатом.
52: 
53: Відсутність перекладу не означає перекладу через третю мову. Відсутність
54: архіву не означає порожній напрямок у старій живій БД. Порівняння при міграції
55: виконується з обраним snapshot, а не зі змінним живим джерелом.
56: 
57: Повний імпорт, публікація, розповсюдження corpus і перемикання старого сайту
58: не виконані самим створенням цих документів.
59: 
60: Деталізація AT: [модель](DATA_MODEL.md), [імпорт](IMPORT_CONTRACT.md),
61: [пошук](LOOKUP_CONTRACT.md), [старі URL](LEGACY_COMPATIBILITY.md).
62: Ліміти admission не дозволяють приховане обрізання; rejected records потребують
63: обліку та погодженого рішення до публікації.

30: ## Як перевіряти при реалізації
31: 
32: - Unit tests: нормалізація, маски/escaping, cursor, fallback, CSV parsers і mappings.

FILE docs/USE_CASES.md
1: # Use cases
2: 
3: Цільовий контракт запропоновано на основі [дослідження](LEGACY.md).
4: Числові та граничні правила визначені у [requirements](REQUIREMENTS.md).
5: 
6: ## Актори
7: 
8: - **Відвідувач:** шукає переклади та завантажує доступні словники без облікового запису.
9: - **Оператор:** через локальний CLI готує набори, звіряє, публікує та відновлює дані.
10: - **Старий клієнт/посилання:** відкриває раніше опублікований URL.
11: 
12: ## UC-01 — Точний пошук
13: 
14: Відвідувач вибирає мову джерела й призначення, вводить слово або фразу.
15: Система показує відповідні вихідні написання та всі їхні переклади сторінками.
16: Написання з даних зберігається; пошук не залежить від регістру.
17: Порожній запит повертає форму, відсутність збігів — явний порожній результат.
18: Невідома мова — помилка вводу; відома пара без даних — «пара недоступна».
19: 
20: ## UC-02 — Пошук за маскою
21: 
22: Відвідувач явно обирає режим маски та вводить, наприклад, `UKR*` або `S?IE*`.
23: `*` відповідає нулю або більше Unicode code points, `?` — одному code point
24: після full case fold та NFC (не grapheme). Широка маска не обходить ліміти й timeout. Наступна сторінка
25: продовжує той самий набір, порядок і версію даних. Буквальні `*`/`?` можна шукати
26: в точному режимі. Відвідувач розрізняє неповну сторінку та завершену видачу.
27: 
28: ## UC-03 — Мова інтерфейсу
29: 
30: Відвідувач обирає UI-мову незалежно від мов перекладу. За відсутності вибору
31: використовується підтримувана мова з `Accept-Language`, далі налаштована основна.
32: Відсутній переклад UI має явний fallback; код локалі словника не втрачається.
33: 
34: ## UC-04 — Завантаження словника
35: 
36: Відвідувач бачить наявні напрямки й завантажує CSV.gz опублікованої версії.
37: Файл містить чотири поля без заголовка: мова джерела, мова призначення,
38: вихідний текст, переклад. Доступні версія, кількість рядків і checksum.
39: Відсутній напрямок не отримує порожнього «успішного» експорту.
40: 
41: ## UC-05 — Підготовка міграції
42: 
43: Оператор надає явний шлях до незмінного snapshot/експорту. Система інвентаризує
44: його, визначає формати, рахує записи, перевіряє Unicode, gzip, локалі й дублікати.
45: Помилкові записи потрапляють у звіт з причиною та позицією, а не зникають.
46: Dry-run не змінює активного набору. Виявлена неповнота потребує окремого рішення.
47: 
48: ## UC-06 — Імпорт і публікація
49: 
50: Оператор імпортує перевірений snapshot у staging, звіряє результат і публікує
51: цілісну версію. Повтор після збою не подвоює дані. Пошук до завершення публікації
52: бачить попередній набір. Невдалий імпорт не змінює його. Без проходження перевірок
53: публікація недоступна; винятки мають бути явно зафіксовані.
54: 
55: ## UC-07 — Старе посилання
56: 
57: Клієнт відкриває підтримуваний старий URL. Адаптер переносить параметри пошуку
58: і мов у новий контракт без зміни значення тексту. Невідомий маршрут повертає
59: явну помилку, а не непомітно інший пошук. Підтверджений перелік — у [LEGACY_COMPATIBILITY](LEGACY_COMPATIBILITY.md);
60: додаткові server aliases потребують OQ-04.
61: 
62: ## UC-08 — Відновлення та відкат
63: 
64: Оператор відновлює backup на окремій цілі, перевіряє набори й контрольні запити.
65: У разі проблем перемикає активну версію назад або повертає трафік старому сайту.
66: Система не видаляє старий snapshot під час перемикання.
67: 
68: ## UC-09 — Збереження історичних метаданих
69: 
70: Якщо є dump БД, оператор переносить доступні `count`, `status`, `queries`
71: з описом походження й невизначеностей. Якщо доступні лише чотирипольні CSV,
72: звіт прямо вказує, які дані відсутні. З них не виводяться вигадані ваги, статуси
73: чи статистика. Відсутні дані не блокують читання збережених перекладів.

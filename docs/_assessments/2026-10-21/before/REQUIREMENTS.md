# Requirements

Статус: запропонований базовий контракт; підтверджений користувачем обсяг і
відкриті питання — у [INDEX](INDEX.md). Усі acceptance tests поки **заплановані**.

## Межі

Перша реалізація — словниковий вебсайт на Go і CLI оператора. Зберігаємо
напрямлені зв'язки між текстами в локалях, включно з фразами та власними назвами.
Автоматичний переклад, LLM, облікові записи, публічне редагування, модерація,
морфологічний/семантичний пошук та новий збір популярності не входять у базову версію.
Зворотний переклад і транзитивні зв'язки не генеруються без окремої вимоги.

## Функціональні вимоги

| ID | Контракт | Критерій приймання |
|---|---|---|
| FR-01 | Довідник зберігає всі імпортовані коди локалей; наявність локалі, UI-перекладу і напрямку — різні ознаки. | AT-01: `en-gb` і `en-us` окремі; `eo-xx`/`la-va` не відкидаються через сучасну валідацію тегів; відсутня пара показана явно. |
| FR-02 | Точний пошук використовує ключ NFC + Unicode case folding; оригінальний текст незмінний. Запит обрізає лише крайні пробіли. Діакритика, пунктуація і внутрішні пробіли значущі. | AT-02: регістр і канонічно еквівалентний Unicode збігаються; апострофи/лапки зберігаються; різні оригінали з одним ключем повертаються всі. |
| FR-03 | Режим маски явний: тільки `*` і `?` спеціальні; решта символів буквальні. Семантика застосовується до нормалізованого ключа. | AT-03: `*`, `?`, `%`, `_`, `\\`, кирилиця й combining marks перевірені; точний режим шукає буквальні `*`/`?`; SQL-метасимволи не розширюють маску. |
| FR-04 | Пошук обмежений і має стабільну пагінацію на одній версії набору; однакова локаль джерела й призначення допустима за наявності даних. | AT-04: кілька сторінок без пропусків/повторів; незавершена видача має cursor; `sr-rs → sr-rs` доступний; зміна версії не змішує сторінки. |
| FR-05 | Вебформа працює без JavaScript, має зрозумілі помилки, порожній результат і незалежну UI-мову з fallback. | AT-05: пошук у браузері без JS; unknown locale, no match і unavailable pair розрізняються; відсутній UI-ключ має fallback. |
| FR-06 | Експорт наявної пари — UTF-8 CSV.gz з чотирма полями, без заголовка, з версією, кількістю логічних записів і SHA-256 файлу. | AT-06: декомпресія та CSV-парсинг відтворюють точну множину напрямлених зв'язків версії, включно з лапками й переносами рядків. |
| FR-07 | Інвентаризація та dry-run не змінюють джерело чи активні дані; кожен вхідний файл має hash, розмір, формат і результат перевірки. | AT-07: пошкоджений gzip, хибний UTF-8, невідомий формат і невідповідність локалей назві файла позначені; active dataset незмінний. |
| FR-08 | Імпорт потоковий, повторюваний і виконується у staging. Ідентичний snapshot з тим самим parser/mapping не створює дубліката опублікованого набору. | AT-08: збій після batch і повтор дають той самий результат, що чистий запуск; жодних часткових наборів у пошуку. |
| FR-09 | Кожен запис враховано: прийнятий, точний дублікат або відхилений з причиною. Значення та походження прийнятого запису збережені. | AT-09: `parsed = accepted_unique + duplicates + rejected`; помилка, за якої неможливо визначити межі CSV-запису, робить файл failed, а не «повним»; unaccounted files = 0. |
| FR-10 | Публікація дозволена лише після звіряння; заміна активної версії атомарна. Невирішені помилки блокують публікацію, погоджені винятки входять до маніфесту. | AT-10: конкурентний пошук бачить цілком стару або нову версію; провал перевірки блокує publish; rollback повертає попередню. |
| FR-11 | Переносяться доступні legacy-метадані без зміни значення; відсутні поля залишаються unknown. | AT-11: CSV4 не отримує `count=1/status=1`; DB-export зберігає нульові та невідомі статуси; timestamp без timezone не оголошується UTC. |
| FR-12 | Сумісність старих URL визначена явним переліком і тестами. Мінімальна пропозиція — параметри `hn=sel/pre`, `il`, `ol`, `iw`, `ul`; точний шлях після OQ-04. | AT-12: Unicode, пробіли й percent-encoding не втрачаються; `pre` має текстове представлення; невідомий handler не видає чужий успішний результат. |
| FR-13 | Backup охоплює активні дані, маніфести, provenance, метадані й необхідні артефакти; restore перевіряється на окремій цілі. | AT-13: після restore збігаються hashes, counts, active version і контрольні запити; відкат не потребує запису у стару БД. |

## Загальні правила приймання

Оригінал — декодовані значення полів без очищення; вихідні архіви зберігаються
окремо для відтворення байтів. Дублікат — однакові чотири оригінальні поля
в межах набору; його походження та кількість входжень не втрачаються.
Колізія нормалізованих ключів не є дублікатом.

Відсутність перекладу не означає перекладу через третю мову. Відсутність
архіву не означає порожній напрямок у старій живій БД. Порівняння при міграції
виконується з обраним snapshot, а не зі змінним живим джерелом.

Повний імпорт, публікація, розповсюдження corpus і перемикання старого сайту
не виконані самим створенням цих документів.
